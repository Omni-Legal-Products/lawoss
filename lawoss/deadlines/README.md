# Document → native review → OKF → local ICS

Implementation follows the [limited deadline scope in spec 0005](https://github.com/Omni-Legal-Products/lawOSS-like-SK-CZ/blob/82a931f4d47f6ba5116d8bf1b50fac5bf0b376a3/specs/0005-lehoty-timeline.md) and [live OKF read-model ADR](https://github.com/Omni-Legal-Products/lawOSS-like-SK-CZ/blob/main/decisions/0014-pohlady-z-okf-vzdy-zive-a-konzistentne.md). Product authorization for this local implementation does not approve a legal RulePack.

`LAWOSS_DEADLINE_WORKFLOW=1` admits the new candidate workflow on the existing Lehoty page. The default is off. Disabling admission preserves existing records and read-only trust verification. It does not enable upstream calendar, scheduled jobs, connectors, or agent calculation tools. The two bundled profiles are explicitly `synthetic_only`, with no reviewer or review timestamp. Real confirmation/export stays unavailable until a responsible lawyer separately approves an exact supported CZ/SK rule and its independent oracles. There is no production approval bypass or developer environment flag for this legal gate.

All native deadline queries and component state are owned by server URL, credential/auth generation, complete practice scope, workspace and matter. Owner switches cancel reads and prevent late mutation/excerpt results from publishing into another connection. The native page selects a concrete matter and current prepared sources, follows all document read cursors, and captures exact excerpts. A manual path works without a model. Missing actual service, ambiguous recipient/document identity, contradictory count/unit, partial OCR and excluded scenarios remain blocking. Selecting an ordinary scenario cannot erase evidence conflicts. Source dates and download times never supply missing legal service.

One L2 `task` in `memory/<candidateId>.md` is canonical. The reserved `lawoss-deadline-v1` tag, `deadline_` ID namespace and `LAWOSS deadline workflow v1` body section identify managed records. The compact JSON body is versioned and bounded to 512 KiB/64 revisions/20 refs per revision. Damaged managed records fail closed instead of falling back to legacy attribution. Other body sections and append-only History survive writes. External tools should preserve managed records or propose a new revision through this workflow.

The full serialized file hash is the byte CAS. The separate semantic revision excludes state, export/host metadata and observation `retrievedAt`. Dedupe uses stable scoped source lineage and logical locator identity; prepared content-version IDs do not become candidate identity. Edits require the current full-file hash; replacement of a logical clause requires `supersedesRevisionHash`. All canonical mutations share the existing `.okf-write.lock` with the ordinary OKF writer. Lock callbacks are synchronous.

Native decisions use the shared HostDecisionPort. The HTTP decision route requires the native host token; owner bearer and agent requests cannot answer it. The host rechecks the exact review binding after the dialog and the domain rechecks source bytes and CAS before commit. Local runtime receipt-consumption metadata prevents resurrecting an old confirmation by restoring pre-revocation Markdown. It contains only scope fingerprints, receipt/operation IDs, action and binding hash; it is not another deadline/calendar store. Copied or moved matter roots need new local review. Textual `verified`, `by` and `at` remain legacy attribution, not managed authority.

The single canonical commit records confirmation and `export_pending`. An ICS failure preserves that confirmed record and exposes a retryable `export_failed` state. Export uses the existing pure renderer, date-only DTSTART, exclusive next-day DTEND, stable UID/SEQUENCE and host-fixed DTSTAMP. Retry preserves bytes. Files are staged/flushed/renamed and checked against owned hashes; foreign files, symlinks, source escapes and external edits are preserved. Files are fsynced before rename; directory fsync is used on Unix and is unavailable through this seam on Windows. Filesystem CAS does not claim an OS sandbox against an unrelated process replacing ancestors concurrently.

Workspace entry and explicit retry recover only that selected matter. A crash after ICS rename is reconciled by the planned hash. A reserved native receipt before an interrupted commit can resume only the same operation/binding. Domain events remain in OKF; the operational audit is a bounded retryable mirror by immutable event ID. No scheduler is installed. Native revocation produces a higher-sequence `STATUS:CANCELLED` projection under the same UID; it does not remove events already imported elsewhere. Stale sources keep the historical date visible, prevent active counts/new confirmation, and permit explicit native withdrawal.

Run from the repository root using the exact CI runtime and **both** server preloads:

```sh
bun test --preload ./apps/server/test-preload.ts --preload ./apps/server/test-preload-lawoss.ts apps/server/src/lawoss/deadlines
bun test --preload ./apps/server/test-preload.ts --preload ./apps/server/test-preload-lawoss.ts apps/app/tests/lawoss-deadline-review.test.tsx lawoss/okf/test/deadline-trust.test.ts
```

The test-only fixture module explicitly injects an isolated artificial approved authority and calendar. Production does not import it. Technical tests do not constitute legal acceptance. Required pilot checks remain separate: responsible CZ/SK legal sign-off; native macOS/Windows dialogs; actual packaged Node resources; filesystem rename/open-file behavior; DST/year-boundary cases; same-mtime source changes; denied/expired decisions; concurrent confirmation; copied workspace; each crash stage; deterministic ICS parse-back; and visible pending/failure/revocation states. Local ICS creation is not sending, service, signing, filing, remote calendar synchronization or a guarantee of deadline monitoring.
