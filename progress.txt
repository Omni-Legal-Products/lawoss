## Codebase Patterns

- Engine global health is independent of instance readiness: finish authenticated cold workspace bootstrap before test configuration/reload, and bound both distinct operations.

- Drain accepted background work before releasing the last server runtime owner; a logically closed SQLite connection can still retain uncached prepared statements. Use the shared cached-query adapter and verify retained statements plus strict Windows removal.
- Delayed mock HTTP handlers must finish their own scenario before reading later mutable fixture state; cancellation of a client does not cancel the server handler.
- Background source refresh and user-triggered generation have separate availability rules; generation always re-reads selected sources before dispatch, while output verification stays conservative during refresh.
- Workspace identity and file paths are separate contracts: moving a folder must not create a new case or silently recreate the old path.
- Reuse DocumentPreparation/OCR and scoped agent plugins; incomplete coverage is a durable result, not a successful empty document.
- Real ISIR datasets and provider credentials stay outside Git; CI fixtures are synthetic.
- Output verification includes visible provenance and valid identity dependencies, not just a machine block. Inspection never grants overwrite ownership.
- Native prompt acknowledgment and terminal task state are separate; keep accepted chats bound to original-source IDs/hashes through retry and reload.
- Same-case copies/aliases require current byte proof and unambiguous reference identity before deduplication. Known idle transports must release capacity while active/waiting owners retain background sync.
- Current source admission and extraction update time are separate: restored bytes must recover their original/descendants after reload. Historical verification receipts must satisfy current structured coverage rules; parsing legacy prose alone never proves completeness.
- A built runtime can prefer a platform-named executable over its canonical alias. Native receipts must verify actual selected bytes/manifests and executable/health versions on initial launch and relaunch, rather than treating equal version strings as binary identity.

- Supplied base text is an independent concurrency precondition: equal mtime can hide changed contents. CI diagnostics are synthetic-only bounded projections; preserve primary failures and verify actual owned child exit.

- Bun SQLite statements need an explicit close lifecycle; cached query statements are finalized by Database.close().
- Provider setup must await the application's workspace engine reload; low-level instance disposal can race the derived runtime configuration write.
- Approval paths must be canonicalized before waiting and compared afterward. Attachment changes also bind the managed SKILL.md.

- Diagnose native bootstrap with fixed completed OTLP span names on an owned loopback receiver; missing completions are not phase-entry proof. Supplementary manual CI may reuse only same-branch ancestor runtime artifacts, preserving manifest checks and the required matrix.
