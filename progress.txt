A server lifetime and a standalone operation have different ownership contracts; never discard policy secrets/throttle state to make cleanup pass.
- Initialize multi-table SQLite schemas in one transaction; prove partial-schema rollback, legacy migration and real native-handle release without changing durability settings or filesystem validation.

- Windows descendant fixtures that require survival after parent exit must request detached lifetime as well as unref; unref alone only changes event-loop accounting. Keep inherited stdio and prove bounded cooperative cleanup with the same strict oracle on actual Windows.
- Real child fixtures must coordinate descendant readiness, direct exit and post-publication writes with explicit handshakes. An independent wall-clock writer can finish before a delayed driver attaches; preserve strict pipe-close assertions and bounded owned cleanup instead of increasing collector budgets.
- Fixed-environment behavioral probes must preserve the default harness and original binary, admit only current first-attempt synthetic CI, and bind producer acknowledgment separately from live environment observation. Protect reserved publication names using target-filesystem equivalence, including case aliases. - Manual sync fixtures must stop both automatic producer domains via real disposers while holding the runtime lifetime; long periodic delays do not disable change-driven scheduling. Background-owner tests opt in explicitly.
- Keep Node ESM preload specifiers distinct from native child/Bun filenames: pathToFileURL for --import, fileURLToPath for script argv, with reserved-character regression paths.
- Exact-runtime exception delivery needs a native capability failure before source work; entry-gate inherited preloads and keep observations separate from compiler-cause/readiness claims.
- Windows fixture source maps must normalize creation and lookup consistently; a host-side win32 model exposes case mismatches but is not actual Windows execution.
- Optional inner observers preserve original await/direct-return adoption and freeze independent closed evidence; disabled callers supply no callback and allocate no wrapper.
- A runner timeout can leave the async test body alive. Capture its observer and freeze statement evidence before cleanup awaits; preserve original drain/error semantics and do not infer the inner awaited cause from a pending statement.
- Public-source build diagnostics preserve the exact entry command and separate-stream framing; fixed milestones and child exit metadata are observations, while missing markers and completed diagnostic jobs do not establish success.

- Private child diagnostics and public upload paths must be distinct; finalize only closed validated projections. Native cleanup failures stay unknown even after direct-child close. - Background source refresh and user-triggered generation have separate availability rules; generation always re-reads selected sources before dispatch, while output verification stays conservative during refresh.
- Workspace identity and file paths are separate contracts: moving a folder must not create a new case or silently recreate the old path.
- Reuse DocumentPreparation/OCR and scoped agent plugins; incomplete coverage is a durable result, not a successful empty document.
- Real ISIR datasets and provider credentials stay outside Git; CI fixtures are synthetic.
- Output verification includes visible provenance and valid identity dependencies, not just a machine block. Inspection never grants overwrite ownership.

- Provider setup must await the application's workspace engine reload; low-level instance disposal can race the derived runtime configuration write.
- Approval paths must be canonicalized before waiting and compared afterward. Attachment changes also bind the managed SKILL.md.
