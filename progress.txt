## Codebase Patterns
- Persistence can retain a captured storage object across test modules; install complete SSR storage before imports and explicitly own/restore real persist adapters in byte/rehydration fixtures.
- Model-tool schema advertisement, actual tool execution and HTTP validation are separate boundaries; normalize only an explicitly supported absence representation by omitting its JSON property.
- Defer browser-only native fixture imports until native execution; keep exact Bun source discovery separate from postbuild Node helpers without changing cwd/preloads. Bounded diagnostics distinguish request/headers/body/scope and retain ownership refusal evidence without raw identifiers.
- Read-local execution ordering needs explicit action/read/activity provenance with captured full transport scope; manual hydration is not new work. A newer native wait/compaction guards an older response without preventing appropriate fresh-poll recovery; its cleanup cannot erase already observed status authority. Preserve accepted/wait/compaction and exact cancellation ownership. Share proven raw/UI revert boundaries through canonical and rendered history, including coexisting aliases.
- Memoize selected workspace transports from effective resolver/auth/application-owner primitives, while keeping filesystem root separately current; fresh metadata must not detach native inputs by replacing query identity.
- Selected-directory startup readiness requires authenticated whole-body scope verification inside the existing absolute budget; UI/global liveness alone is insufficient, and recovery must not probe missing historical roots.

- Native bootstrap uses the supported authenticated workspace host reload; config persistence/catalogue presence/tool execution/full acceptance are separate evidence. Network ages use only monotonic Network clocks; bounded document epochs distinguish historical pending observations from current requests, with explicit dropped correlations and actual failing-case probes. Built-server helper gates follow normal CI builds.
- Runtime SQLite lifetimes capture path/generation and span accepted async operations. Shared owners preserve each other's stores and pending synchronization; failed native cleanup retains its exact resources/errors for explicit recovery before any successor proceeds. Verify actual handles and ordinary removal in Bun and Node without GC.
- Request abort, response-reader cancellation and lock release are separate responsibilities. Verify actual upstream close through the authenticated proxy while another stream stays alive; preserve metadata timeout, accepted detached work, normal completion and primary errors.
- Restore shared fixture state through an outer cleanup scope that begins before awaited startup and cannot be bypassed by failed teardown; verify exact original errors and owned listener release.
- Synchronization status evidence belongs to actual tracked owners, not transient UI query observation. Bounded disabled status observers must add no fetch, retain freshness/unknown/error/run guards, release at last reference and allow ordinary postrelease GC while enabled UI refresh still works.

- Workspace identity and file paths are separate contracts: moving a folder must not create a new case or silently recreate the old path.
- Reuse DocumentPreparation/OCR and scoped agent plugins; incomplete coverage is a durable result, not a successful empty document.
- Real ISIR datasets and provider credentials stay outside Git; CI fixtures are synthetic.
- Output verification includes visible provenance and valid identity dependencies, not just a machine block. Inspection never grants overwrite ownership.
- Native prompt acknowledgment and terminal task state are separate; keep accepted chats bound to original-source IDs/hashes through retry and reload.
- Same-case copies/aliases require current byte proof and unambiguous reference identity before deduplication. Known idle transports must release capacity while active/waiting owners retain background sync.
- Current source admission and extraction update time are separate: restored bytes must recover their original/descendants after reload. Historical verification receipts must satisfy current structured coverage rules; parsing legacy prose alone never proves completeness.
- A built runtime can prefer a platform-named executable over its canonical alias. Native receipts must verify actual selected bytes/manifests and executable/health versions on initial launch and relaunch, rather than treating equal version strings as binary identity.

- Supplied base text is an independent concurrency precondition: equal mtime can hide changed contents. CI diagnostics are synthetic-only bounded projections; preserve primary failures and verify actual owned child exit.
